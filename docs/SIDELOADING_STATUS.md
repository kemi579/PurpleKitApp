# PurpleKit sideloading status

## Implemented

- SwiftUI My Apps library with IPA import, search, sorting, details, export and confirmed deletion.
- Library extraction runs in a background task; the UI shows a loading state.
- Apple Developer Portal sign-in and 2FA are connected through SideSign.
- Authentication sessions and signing key material are stored in Keychain.
- The saved session and certificate are restored when the application starts.
- The selected Apple developer team is persisted and used by the signing service.
- Installation preflight validates credentials, connects Minimuxer and fetches the real device UDID **before** provisioning or signing.
- Local pairing imports are validated before atomic replacement. Pairing files are protected and excluded from backups.
- Signing checks that the certificate belongs to the selected team and is not expired.
- Bundle IDs are rewritten consistently to stable team-specific identifiers in the signing workspace, avoiding collisions with IDs owned by another team.
- Each app extension gets its own App ID and provisioning profile.
- Profiles are checked against bundle ID, team, certificate, device UDID and expiry before signing.
- Signed IPA output names are unique; another build is not silently overwritten.
- My Apps can install an already signed IPA without signing it again.
- Installation reads the actual signed bundle ID, checks device provisioning, transfers using AFC and awaits InstallationProxy before reporting success.
- Service entry points reject overlapping operations. Connection readiness is checked again after signing.
- Standalone Swift package tests cover real/invalid UDID formats and provisioning mismatches.
- CI runs these tests before producing an unsigned application archive.

## Setup on a real iPhone

1. Install PurpleKit using a compatible external sideloading tool.
2. Obtain a pairing file for this iPhone using a compatible PC/Mac pairing tool, then import it in PurpleKit Settings.
3. Enable a compatible local VPN for the Minimuxer connection.
4. Sign in to Apple ID, select the developer team and request a development certificate.
5. Import an eligible IPA in My Apps, open its details and choose Sign and Install.
6. For a previously signed IPA, choose Install IPA; no Apple sign-in is required if its profiles remain valid for this device.
7. If requested by iOS, enable Developer Mode and trust the developer through the system settings.

Pairing cannot be generated by reading secrets outside the normal application sandbox. A first-time host pairing remains necessary for this workflow.

## Validation limits

A successful CI build verifies compilation and packaging. The validation unit tests check policy rules, not Apple services, cryptographic verification, device connectivity or actual installation.

The complete Apple ID -> pairing -> signing -> device installation flow still requires a physical iPhone test. No physical-device validation is claimed by this change.

Not all IPA packages can be installed: encrypted App Store packages, unavailable bundle identifiers, unsupported capabilities, developer-account limits and incompatible iOS versions may prevent signing or installation. Automatic periodic refresh, installed-app inventory, capability/App Group remapping and universal IPA compatibility are not implemented.

The CI download is an **unsigned** PurpleKit IPA and still requires signing by a compatible sideloading tool. Third-party dependencies and their notices are documented in THIRD_PARTY_NOTICES.md.
